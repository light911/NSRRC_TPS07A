做了什麼

功能範圍

原本 setBackLightColor 已經註冊在 dcss 設定檔、也已經路由到 CVLS queue， 但處理函式是一個空的 pass，而且從不回報完成 —— 任何呼叫它的人都會一直卡在 operation active 狀態。

現在它是一個可用的操作：

硬體是 RGBW 機種，一色一通道： ch1 red ch2 green ch3 blue ch4 white

  • 顏色切換　先設目標通道功率，再關掉其他三個，最後才 enable 目標 —— 兩個顏色不會同時亮，連一瞬間都不會。
  • 強度　0–100%，線性對應到 0 – max_power 的原始通道功率。
  • master enable 完全不碰　它跟著 MD3 phase 走。所以使用者設好的顏色與亮度可以撐過 phase 切換，燈回來的時候設定還在。
  • 狀態回讀　新增 backlight_status 字串，BluIce 切換顏色時能把滑桿還原成該顏色上次用的亮度。
  • auto center 保護　非白光直接拒跑，白光則先強制校正亮度。

資料怎麼流動

架構 · 為什麼需要 Par

CV-LS 跑在自己的 OS process 裡。這是整份文件最需要先理解的一件事： publish_status() 有兩條不同的出口，因為它的兩個讀者位在不同的地方。

介面契約

operation · string · Par

Operation

setBackLightColor <colour> <intensity>

  colour     red | green | blue | white | off
  intensity  0 – 100 (%)

  off   四個通道全部關掉，但保留各自的功率，下次開回來還是原本的亮度
  失敗  回 htos_operation_completed ... failed <原因>，BluIce 端跳 log_error

狀態字串

backlight_status = <colour> <intensity> <master> <red> <green> <blue> <white>

  例   red 60 on 60 33 20 20
       off 60 off 60 33 20 20
       unknown 0 disconnected 0 0 0 0      ← CV-LS 沒有回應

  後四欄是各顏色的強度百分比，不是原始功率。這樣 BluIce 不需要自己
  再存一份 max_power 就能還原滑桿。

發佈時機共四個：每次設定成功後、master 開關後、dcss 註冊字串時、以及 DHS 啟動時。

Par 的 key

Par['CVLS.color']       str   red / green / blue / white / off / mixed / unknown
Par['CVLS.intensity']   int   0 – 100
Par['CVLS.master']      str   on / off / disconnected

設定值

Config.py · CVLS 區塊

參數目前值意義
max_power100 強度 100% 對應到的原始通道功率。硬體上限是 1000，但這條線實際只用到 30–50 的區間，所以把天花板壓低，整條滑桿才都在有用的範圍內。
autocenter_intensity30 auto center 執行前會強制套用的白光亮度。重新做背景影像校正時才需要改。

這組值剛好讓百分比和原始功率 1:1 對應（30% × 100 ÷ 100 = 30）， 而 30 正是導入前白光通道原本的功率值 —— 也就是說 auto center 的 亮度基準跟改動前一致。

auto center 保護

centerLoop 的前置檢查

auto center 是拿樣品去比對一張背景參考影像，那張影像是在白光、固定亮度下拍的。 使用者改了顏色或亮度，比對基準就跟著跑掉，而且是默默地失準。 所以 centerLoop 一開頭會先問 prepareBackLightForAutoCenter()：

  • 不是白光　直接不跑。發 warning 給使用者，operation 回報 failed 並在訊息裡講出當下是什麼顏色。off 和 unknown（CV-LS 斷線）也算在內。
  • 是白光　亮度已經是設定值就直接跑；不是就送 set_intensity，然後輪詢 Par 等確認再開始，不是隨便 sleep 一個數字賭它做完了。
兩個可以推翻的判斷

亮度確認逾時（3 秒）不擋、只記 warning 然後照跑。 能走到這一步表示顏色已經確認是白的，只有亮度沒確認；為了燈反應慢就擋掉定心，代價可能比較高。 要改成嚴格擋下來的話是一行的事。

master enable 沒納入檢查。 centerLoop 在 phase≠0 的分支本來就會 master_on，phase=0 時 MD3 的 phase callback 也已經開好了， 再加一層怕會跟 phase 切換搶時序，反而擋掉本來會成功的情況。

以後要注意的地方

設計取捨 · 已知缺口 · 踩過的坑

  • 設計取捨

    沒有週期性回讀

    有人轉 CV-LS 前面板旋鈕、或用它的 web 介面改設定，DHS 完全不會知道， backlight_status 和 Par 就會過期。 連帶影響：auto center 的白光保護也擋不住這種情況。 要補這個缺口就得加週期 poll（&M? 可以查最後是哪個介面改的）。

  • 已知缺口

    沒有斷線重連

    CVLSController.connect() 只在 __init__ 呼叫一次，monitor 迴圈沒有重連邏輯。 而 legacy socket 同時只允許一個 client（要用 &ALK 踢人）。 如果有人用別的工具連上去把 DHS 擠掉，之後所有指令都會靜默失敗。 至少狀態字串會轉成 disconnected，GUI 會變灰，不會假裝一切正常。

  • 既有問題

    switchSampleEnvironment 仍然是空的

    它就在我改的那段隔壁，一樣是 pass 而且不回 operdone —— 跟 setBackLightColor 原本的卡死問題完全相同。這次刻意沒動它 （它牽扯到背光板氣動進出，不只燈光），但問題還在。

  • 踩過的坑

    epicsinit.py 是 CRLF 換行

    用 Python 文字模式讀寫會把整個檔案轉成 LF，diff 會變成 1431 行全改。 這次已經轉回來了。要用腳本改這個檔的話請用 binary 模式，或事後檢查 file epicsinit.py。其他三個檔本來就是 LF。

  • 踩過的坑

    addInput 的第三個欄位是「相等比對」，不是萬用字元

    calculateOutput 做的是 if {$value != $triggerState}。 所以 addInput "$obj contents {} {...}" 的意思是 「只有內容等於空字串時才放行」—— system_idle 這樣用是對的（閒置時內容真的是空的）， 但想表達「只要這個字串活著就好」是做不到的。那種情況要改用 -state， DCS::Button 把 -state disabled 當成蓋在 gate 之上的覆寫。

  • 踩過的坑

    ::mediator register 需要先 announceExist

    mediator 只會把更新送給已經 announce 過自己的 listener，否則請求會躺在 futureRequests 裡永遠不送。純 ::itk::Widget 沒有 ::DCS::Component 基底可以 announce，所以要 直接對物件註冊（$obj register $this attr callback）， 不要走 mediator。狀態字串一開始就是這樣才會動的。

  • 踩過的坑

    operdone 的 status 寫死成 normal

    要回報非 normal 的狀態只能走 ('updatevalue', op, status, 'operation_completed', handle) 這條路。 但那條路原本沒有把 operation 從 operationRecord 移除， 失敗過的 operation 之後遇到 abort 會被重複回報完成一次。已抽成 _drop_operation_record() 給兩條路共用。

  • 踩過的坑

    .dat 預設值全 0 曾經造成歸零棘輪

    預設值 off 0 off 0 0 0 0 讓各顏色記住的強度都是 0， 按顏色就送 <colour> 0，硬體功率被設成 0，讀回來還是 0 —— 單向鎖死。現在 BluIce 端有 fallback（該顏色的值 → 畫面當前值 → 預設 20%）， 但改 .dat 預設值時還是要留意這個方向性。

  • 環境

    /usr/local/dcs/BluIceWidgets 是 symlink

    指向 /data/dcs/BluIceWidgets。改 repo 就是改線上，沒有額外的部署步驟， 但也表示編輯當下就生效，下一個開 BluIce 的人就會拿到。

  • 行為

    「設了顏色卻不亮」先看 master

    master enable 由 MD3 phase 控制，GUI 刻意不碰。不在 Centring phase 的時候燈本來就是暗的， 面板最下面那行會寫 master: off (MD3 phase)。這是正常的，不是壞掉。
